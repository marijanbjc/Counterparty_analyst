ЗАПУСК ПРОЕКТА

0. Положить снапшот в docs/internal_files/contractors_audit.snapshot.json
   Скопировать .env.example в .env и заполнить POSTGRES_PASSWORD, AUTH_PASSWORD, LLM_API_KEY

Все команды ниже выполняются ИЗ КОРНЯ Counterparty_analyst,
кроме фронтенда — у него свой package.json в src/ui.


1. БАЗА ДАННЫХ
   docker compose --project-directory . -f devops/docker-compose.yml up -d db
   pip install -r requirements.txt
   python app.py load-data

   Загрузчик идемпотентен: если снапшот не менялся, повторный запуск пропускается.
   Перезалить принудительно: python app.py load-data --force


2. BACKEND (терминал 1)
   python app.py serve
   -> http://127.0.0.1:8000
   Проверка: curl http://127.0.0.1:8000/api/health


3. ФРОНТЕНД (терминал 2)
   cd src/ui
   npm install
   npm run dev
   -> http://localhost:5173

   ВАЖНО: npm install запускается в src/ui, package.json лежит там, а не в корне.
   ВАЖНО: vite слушает IPv6, поэтому открывать localhost:5173, а не 127.0.0.1:5173.

   Собрать статику, чтобы её раздавал сам backend с http://127.0.0.1:8000:
   cd src/ui && npm run build


4. MCP-СЕРВЕР (терминал 3)
   python app.py mcp             # stdio: так его запускает MCP-клиент
   python app.py mcp --http      # http://127.0.0.1:8765/mcp, чтобы посмотреть вручную

   По умолчанию транспорт stdio: сервер ничего не выводит и ждёт клиента.
   Агентный слой, который его использует, пока в разработке, поэтому для
   ручной проверки каталога из 24 инструментов нужен флаг --http.
